# Architecture

Living document. Update it in the same change whenever a component, data model, boundary or decision changes. Last major revision: 2026-11-04 (v1 built; plan from 2026-11-03).

## 1. Product in one paragraph

Theirside tells a team, within minutes, when a specific third-party provider endpoint starts failing, e.g. "Acme Cards `POST /v2/cards/:id/activate` failing 38% for 6 min (normally 0.2%), other Acme endpoints OK". A drop-in SDK records outgoing HTTP calls. A collector stores them, learns a baseline per endpoint, scores health and alerts. Outputs are a developer dashboard, a health API and an embeddable status page the customer shows its own clients. Out of scope: monitoring the host app itself (Sentry does that).

## 2. Editions and licensing

One codebase and one image: self-hosted for free, with paid features unlocked by a licence key (self-hosted) or a cloud plan.

Rule: **anything a single team needs to catch provider problems is free; what a manager, compliance team or larger company needs is paid. Never move a free feature to paid.** Paid code goes in `ee/` and is reached only through an entitlement check (§4).

**Free (OSS, self-hosted):** SDK; collector; baselines and scoring; alerts to Slack, email and webhook with the provider-ready incident summary; dashboard; health API; one embeddable status page (with a small "Powered by Theirside" footer link); one org with unlimited projects and environments; admin-token login; retention set by the operator.

## 3. Components

```
 host app (Node)                               customer infra (self-hosted) or our cloud
┌──────────────────────┐   gzip JSON batches   ┌──────────────────────────────────────────┐
│ app code             │  POST /v1/ingest      │ collector (one Docker image)             │
│  └ fetch/undici ─┐   │ ────────────────────▶ │  ingest API ─▶ storage (Postgres)        │
│  └ http/https ───┼▶ SDK (buffer, batch,     │  scheduler: partitions, baselines,       │
│  └ axios ────────┘   │  drop on failure)     │             scoring, incidents, alerts   │
└──────────────────────┘                       │  query API: /v1/health, /v1/incidents    │
                                               │  dashboard SPA, /status/:token, embed.js │
                                               │  alert senders: Slack, email, webhook    │
                                               └───────────────┬──────────────────────────┘
                                                               │ opt-in, anonymous rollups (later)
                                                               ▼
                                                    network service (cloud, not in this repo)
```

### 3.1 SDK (`packages/sdk`)
- `init(config)` instruments `fetch`/undici via `diagnostics_channel`, Node `http`/`https` via `http.client.*` channels where available or wrapping `request`/`get` otherwise. Axios is covered through those. One call is counted once.
  - undici: `undici:request:create` / `:headers` / `:error`. Request headers are a string on Node 18 and an array later; response headers are an array of Buffers on all supported versions.
  - http/https: `http.client.request.start` fires with the `ClientRequest` on every supported version (verified 18.18.0, 18.20, 20.9, 20.20, 22, 24). `http.client.request.error` is missing on 18 and early 20, and no channel reports client-side timeouts or caller aborts, so on all versions the outcome comes from observing that request's own events by wrapping its `emit` (no listeners are added, so the host app's error semantics don't change). Node < 18.18 or runtimes without the channel fall back to wrapping `http(s).request/get`.
  - A call is recorded at response headers (status, time to headers) or at a failure before them. Each `ClientRequest` is tagged with a symbol so wrappers stacked by X-Ray/OTel/nock never cause a double count.
  - Channels are subscribed once per process and never unsubscribed; module-level dispatchers forward to the active client (works around a Node 18.18 bug where a channel that lost its last subscriber never delivers again).
- Must coexist with AWS X-Ray `captureHTTPsGlobal`, Sentry/OpenTelemetry http instrumentation and `nock`.
- Auto-discovery (default `autoDiscover: true`; `trackUnknownHosts` is a deprecated alias): every third-party host is recorded with `provider: null` except loopback, private/link-local ranges, cloud metadata, internal names, telemetry hosts, the collector, `OTEL_EXPORTER_OTLP_*`/`SENTRY_DSN` hosts, `internalHosts` and hosts hidden or marked internal in the dashboard (`packages/shared/src/exclusions.ts`, `packages/sdk/src/discovery.ts`). Listed `providers` keep their name and routes. `autoDiscover: false` = listed providers only.
- `untracked(fn)` (`src/untracked.ts`): an `AsyncLocalStorage` scope checked in `Recorder.begin`, the single entry for http and undici capture, so calls started inside `fn` or async work it spawns are never recorded; `track()` is explicit and still records. For user-supplied URLs (image downloads, customer webhooks) that aren't providers.
- Route learner (`RouteLearner` in `templating.ts`): per host + parent template + position, sightings per literal value as 32-bit hashes with counters. Path privacy (`pathPrivacy`, per call via `PathPolicy`): `strict` (default) sends a literal only when every word of it (`pathWords`: separators and camelCase) is in the vocabulary (`vocabulary.ts`, generated by `tools/vocabulary`) or the provider's allowed words; strict sends such a literal from the first sighting. `balanced` skips the vocabulary check and sends a literal only from its 5th sighting (`:id` before; results with a provisional `:id` aren't cached). In both, version segments are exempt and > 16 distinct values → `:id`. Slots are keyed by provider (`PathPolicy.key` = `@p:<name>`) when the SDK knows the host's provider (init() or a remote-config provider), else by host. The mode per provider is the dashboard's (remote config `providers[].pathPrivacy`) when set, else init()'s; `providers[].allowedWords` adds words. Explicit routes (init, dashboard, catalog `routes`) bypass it. Tenant-style subdomains share one key `*.domain`: after 20 distinct subdomains of a domain (`TENANT_FOLD_SUBDOMAINS`, the collector's fold threshold; domain = host minus its first label, no PSL in the SDK), or at once for the remote config's `tenants`. Capped at 500 slots × 17 counters + 2000 learned positions + 1000 domains × 20 label hashes + 1000 folded domains, all with least-used eviction (lowest tenth dropped when full, counts halve every `max` inserts); cached templates count a use on their slots so busy paths stay. The templater's per-host sets are capped at 500 hosts (LRU).
- Remote config: `GET /v1/sdk-config` (ingest or read key) every 60 s with ETag, in the background; failures keep the last good config. Carries hidden/internal host patterns, routes per provider (the project's, then catalog `routes` for every catalog provider that ships them), per-provider `pathPrivacy` (dashboard) and `allowedWords` (dashboard, then catalog `allowedWords`); a provider is sent when it has any of these, or (within a 256 KiB budget) when it has more than one host or pattern, so the SDK can key its learner by provider, `tenants` (the `*.domain` patterns the directory folded, for the route learner; absent from older collectors), sampling (`packages/shared/src/sdk-config.ts`). Precedence: hidden/internal always apply; `init()` routes first, then remote routes. A 404 (collector without the endpoint) switches auto-discovery off for the process (see §4 protocol).
- Ring buffer (`maxQueue`, drop oldest), flush on interval or batch size, unref'd timers, backoff up to 60 s, one batch in retry. Uses un-instrumented transport so it never records itself: the original `http.ClientRequest` captured at module load plus a dedicated agent, which also keeps the uploads out of X-Ray/OTel traces. Sockets are unref'd except during `shutdown()`. Reports dropped-event counts and the last flush error.
- `shutdown()` flushes with a 2 s cap; also run on `beforeExit` and `SIGTERM` (one-shot listener; if no other SIGTERM listener exists the signal is re-raised after the flush so the default exit still happens).
- Never throws into user code; target overhead p99 < 0.1 ms per call (measured: `docs/benchmarks.md`).
- Zero runtime dependencies; `packages/shared/core` (no zod) is bundled in by tsup. CJS + ESM + d.ts, Node 18.18+.
- Identical for self-hosted and cloud: switching is `endpoint` + `apiKey`.

### 3.2 Shared (`packages/shared`)
- Event schema (TypeScript types + zod), ingest protocol version, outcome enum.
- Endpoint templating: explicit routes win; auto-collapse IDs (ints, UUID/ULID/ObjectId, long hex, token-like strings, prefixed IDs like `cus_123`, emails, any 12–19 digit run); strip query/fragment; 200 templates per host cap then `/:overflow`. Exact rules: `docs/privacy.md`.
- Latency histogram: 18 fixed buckets, upper bounds 1, 2, 4 … 65 536 ms then +∞ (`LATENCY_BUCKET_UPPER_MS`); quantiles by linear interpolation inside a bucket. Changing the buckets is a breaking change for stored rollups.
- Two entry points: `@theirside/shared/core` (dependency-free: constants, outcomes, histogram, templating, host patterns, network row) and `@theirside/shared` (adds the zod schemas).
- Network aggregate row type (see 5.4), so the format is fixed early.

### 3.3 Collector (`apps/collector`)
- Fastify + `pg`. Config by env only (`apps/collector/src/config.ts`). Stateless HTTP layer; one scheduler leader via Postgres advisory lock, so it can run with several replicas.
- Modules: `ingest`, `storage` (repository interfaces + Postgres implementation), `scheduler`, `scoring`, `incidents`, `alerts` (channel adapters), `api`, `status-page`, `auth`, `entitlements`, `usage`.
- Serves the dashboard SPA build (`apps/dashboard`, Vite + React + uPlot, hash routing, built into `apps/collector/public` and shipped in the image) at `/`.
- HTTP surface:
  - SDK: `POST /v1/ingest` (§6).
  - Health API (project API key, `read` scope): `GET /v1/health[?environment=]` (providers → status, score, calls/min, error rate vs normal, p95 vs normal, endpoint breakdown), `GET /v1/incidents[?status=&provider=&limit=]`. Documented in `apps/collector/openapi.yaml`, served at `/v1/openapi.yaml`.
  - Auth (public, §4): `GET /v1/auth/status`, `POST /v1/auth/setup`, `/v1/auth/login` (`{email, password}` or break-glass `{token}`), `/v1/auth/logout`, `/v1/auth/invite/info|accept`, `/v1/auth/password-reset/request|info` and `/v1/auth/password-reset`. `POST /v1/auth/login/2fa` (second step). Own account (signed in): `POST /v1/account/password`, `/v1/account/sign-out-everywhere`, `GET /v1/account/2fa`, `POST /v1/account/2fa/setup|enable|disable|recovery-codes`. Users: `GET /v1/admin/users` (users + pending invites), `POST /v1/admin/users/invites`, `DELETE /v1/admin/users/invites/:id`, `POST /v1/admin/users/:id/reset-link`, `POST /v1/admin/users/:id/sign-out`, `POST /v1/admin/users/:id/disable-2fa`, `DELETE /v1/admin/users/:id`, `GET/PUT /v1/admin/settings/security` (`{require2fa}`).
  - Dashboard API (session cookie with `x-csrf-token` on writes, or `Bearer THEIRSIDE_ADMIN_TOKEN`; `?project=` selects a project, default the first): `/v1/me` (user, auth method, CSRF token), `/v1/admin/overview`, `/v1/admin/series` (1h/24h/7d → 1-min/15-min/2-h buckets, with the endpoint's baseline and incident threshold for the chart band), `/v1/admin/incidents[/:id]`, `/v1/admin/providers` (+ `PATCH /:id` for hosts, routes, support contact, public display name, `isPublic`, `pathPrivacy` (null = the SDK's setting), `allowedPathWords`), `/v1/admin/alert-channels` (§7.1), `/v1/admin/deliveries`, `/v1/admin/sdk-instances`, `/v1/admin/api-keys` (list by prefix with scopes, created, last used; `POST` returns the full key once; `DELETE /:id` revokes, effective at once on that collector and within the 60 s key cache elsewhere), `/v1/admin/status-pages` (list with `limit`/`used`/`canCreate`; `POST`, `PATCH /:id` (title, provider filter, theme), `DELETE /:id`; creation beyond `maxStatusPages` answers 403 `status_page_limit` with an upgrade message), `/v1/admin/settings/thresholds`, provider actions (`PATCH /v1/admin/providers/:id` also takes `displayName`, `hidden`, `internal`, `alertsEnabled`; `POST /:id/merge {into}`, `POST /:id/split {host}`), `/v1/admin/settings/discovery` (`{digest}`); the overview carries `discovery.recent` (first seen < 24 h) and `discovery.overflow` (the `Other` bucket exists). Admin writes need the owner or admin role; PATCH bodies only change the fields they contain.
  - Public: `GET /status/:token` (server-rendered HTML, `?theme=auto|light|dark`, `?providers=<display names>`, `?embed=1`; cached `THEIRSIDE_STATUS_CACHE_SECONDS`, default 30, in memory and via `Cache-Control`), `GET /embed.js` (inserts an auto-height iframe; `data-token`, `data-theme`, `data-providers`).
- Health computation (`modules/api/health.ts`) reuses the scoring code over the last complete 5-minute window and cached baselines; endpoints in an open (non-muted) incident are red. Status-page daily uptime = 1 − incident minutes / minutes in the day (more than 30 incident minutes = outage, otherwise degraded; no traffic and no incident = no data).
- Startup: wait for Postgres (up to ~2 min), apply `migrations/*.sql` in order (tiny runner, advisory-locked, `schema_migrations`), bootstrap, create today's partitions, listen, start the scheduler.
- `AppContext` (`context.ts`) carries config, storage, clock, entitlements resolver, API-key authenticator, sessions and usage limiter; tests build it with a fake clock, cloud can pass its own `EntitlementsResolver`.
- Health: `GET /healthz` liveness, always 200 with `db: ok|unavailable` (an orchestrator must not restart collectors during a DB outage); `GET /readyz` 503 while the DB is unreachable.
- Docker: `docker/Dockerfile.collector` (multi-stage, `pnpm deploy --prod`, runs as `node`, `HEALTHCHECK` on `/healthz`), `docker/docker-compose.yml` (postgres + collector; `--profile demo` adds the demo stack; `THEIRSIDE_VERSION` picks the released image, which is only pulled; `local`, the default, builds the checkout as `:local`). Releases: `.github/workflows/release-collector.yml` on a `v*.*.*` tag (or manual run with a version) runs the collector tests, then pushes `ghcr.io/theirside/collector` for linux/amd64 + arm64 tagged `<version>`, `<major>.<minor>` and `latest` (the last two not for prereleases), with OCI labels, BuildKit provenance + SBOM and a GitHub build provenance attestation.
- Key env vars: `DATABASE_URL` (required), `PORT` (4318), `THEIRSIDE_DEPLOYMENT_MODE`, `THEIRSIDE_PUBLIC_URL`, `THEIRSIDE_BOOTSTRAP_API_KEY`, `THEIRSIDE_BOOTSTRAP_ORG_NAME`, `THEIRSIDE_BOOTSTRAP_PROJECT_NAME`, `THEIRSIDE_ADMIN_TOKEN`, `THEIRSIDE_LICENSE_KEY`, `THEIRSIDE_ALLOW_DEV_LICENSE`, `THEIRSIDE_RAW_RETENTION_DAYS` (30), `THEIRSIDE_ROLLUP_RETENTION_DAYS` (90), `THEIRSIDE_PARTITIONS_AHEAD_DAYS` (3), `THEIRSIDE_SCHEDULER_ENABLED`, `THEIRSIDE_SCHEDULER_INTERVAL_MS` (60000), `THEIRSIDE_SMTP_URL` or `THEIRSIDE_SMTP_HOST`/`_PORT`/`_SECURE`/`_REQUIRE_TLS`/`_USER`/`_PASS`/`_FROM`, `LOG_LEVEL`, `THEIRSIDE_SESSION_MAX_AGE_HOURS` (168), `THEIRSIDE_SESSION_IDLE_HOURS` (24), `THEIRSIDE_TRUST_PROXY` (true; false, a hop count or load-balancer CIDRs), `THEIRSIDE_SECRET_KEY` (≥ 32 characters; required for 2FA), `THEIRSIDE_SECRET_KEY_PREVIOUS` (comma-separated, for rotation), `THEIRSIDE_AUTH_PROXY` (off; header, alb), `THEIRSIDE_AUTH_PROXY_TRUSTED_IPS`, `THEIRSIDE_AUTH_PROXY_HEADER` (X-Forwarded-Email), `THEIRSIDE_AUTH_PROXY_ALB_ARN`, `THEIRSIDE_AUTH_PROXY_AUTO_CREATE` (false), `THEIRSIDE_STATUS_CACHE_SECONDS` (30), `THEIRSIDE_PUBLIC_PATHS_ONLY` (false: a public-facing instance serving only `/status/*`, `/embed.js`, `/healthz`, `/readyz`, without scheduler), `THEIRSIDE_CATALOG_OVERRIDE` (JSON file with extra catalog entries; demos and tests).

### 3.4 Deployment modes
`THEIRSIDE_DEPLOYMENT_MODE=self_hosted | cloud`. The mode only changes defaults (bootstrap org/project from env, auth method, where entitlements come from). Feature checks never branch on mode; they ask entitlements.

## 4. Tenancy, auth, entitlements

- Hierarchy: `org` → `project` → `environment` (string on events, e.g. `production`). Every tenant-owned table has `org_id`, and `project_id` where relevant, from day one, even though self-hosted runs a single org.
- Users (free edition, `modules/auth`): built-in accounts in `users` + `memberships` (migration 005). Every user is equal: the first is `owner`, invited users `admin`, and both may do everything; roles, SSO and an audit log stay paid entitlement flags (`rbac`, `sso`, `auditLog`) and are not built.
  - First run: while no user can sign in, `/v1/auth/status` says `setupRequired` and the dashboard shows the setup page. It creates the first user (and the default org, project and status page if bootstrap didn't), protected by `THEIRSIDE_ADMIN_TOKEN` or a one-time setup code each instance prints to its log at start (stored hashed in `install_meta` as `setup_code:<sha256>`, valid 24 h, all deleted on setup). A credential-less placeholder admin from older bootstraps (`install_meta.bootstrap_admin_user_id`) is claimed rather than duplicated.
  - Passwords: argon2id (`@node-rs/argon2`, 19 MiB, t=2, p=1), 12–256 characters, no composition rules; unknown emails are verified against a dummy hash so timing doesn't reveal accounts.
  - Sessions (`sessions`): a random 256-bit cookie token (`theirside_session`, `HttpOnly`, `SameSite=Strict`, `Secure` when the dashboard URL is https); only its SHA-256 is stored. They end after `THEIRSIDE_SESSION_MAX_AGE_HOURS` (168) or `THEIRSIDE_SESSION_IDLE_HOURS` (24) idle, on sign-out, and for all devices on "sign out everywhere", a password change (except the current one) or a reset; `last_seen_at` is written at most once a minute.
  - CSRF: writes on a cookie session need `x-csrf-token` = HMAC(per-install secret, session hash), returned by sign-in and `/v1/me`; any `Origin` must be the collector's own (or `THEIRSIDE_PUBLIC_URL`'s) and `Sec-Fetch-Site: cross-site` is refused, also on the public sign-in/setup/link endpoints (login CSRF). Bearer requests carry no ambient credential and need neither.
  - Throttling (`auth_throttle`, shared by replicas): 5 failures (password or later 2FA code) for one email in 15 min lock that email for 15 min, existing or not, even for the right password; 30 failures from one address in 15 min block it (passwords, admin token, setup code, unknown link tokens); 3 reset emails per address per hour. The address is `req.ip`, so set `THEIRSIDE_TRUST_PROXY` to the load balancers when clients could forge `X-Forwarded-For`.
  - One-time links (`auth_tokens`, SHA-256 of a 256-bit token, in the URL fragment `#/invite/<token>` so it never reaches logs): invites (7 days, per email, a new invite replaces the older one) and password resets (1 hour, admin-generated or, with SMTP, self-service "forgot password" that answers the same for unknown emails). A reset signs the user out everywhere and lifts a lockout. Emails go through the same SMTP settings as alerts (`modules/mail`); the link is always returned too, with the send error if any.
  - Two-factor sign-in (optional, per user; migration 006): TOTP (RFC 6238, SHA-1, 6 digits, 30 s, ±1 step) set up from the account page in two steps (secret + `otpauth://` URL, then a code proves it), plus 10 single-use recovery codes (16 characters from a 30-letter alphabet, ~78 bits, stored as SHA-256, shown once). With 2FA on, the right password returns `{mfaRequired, mfaToken}` (an `mfa` one-time token, 5 minutes) instead of a session; `POST /v1/auth/login/2fa` takes a code or a recovery code. Each code's step is stored (`totp_last_step`) and only later steps are accepted, so a code works once; wrong codes count against the account like wrong passwords. Turning 2FA off and new recovery codes need the password; another user (or the admin token) can turn a user's 2FA off for a lost phone.
  - TOTP secrets are encrypted at rest (`SecretBox`): AES-256-GCM with a key derived by HKDF-SHA256 from `THEIRSIDE_SECRET_KEY`, the user id as associated data, stored as `v1.<key id>.<iv>.<ciphertext>.<tag>`. Without the key 2FA can't be turned on or required; if it is lost, codes can't be checked (sign-in answers 503 `secret_key_missing`) and users sign in with recovery codes or have 2FA turned off by another user. Rotation: set the new key and the old one in `THEIRSIDE_SECRET_KEY_PREVIOUS`; each start re-encrypts secrets under the current key, after which the old key can be removed.
  - "Require 2FA for everyone" (`orgs.require_2fa`, Settings → Users): needs the key and the person switching it on to have 2FA. A password user without 2FA can then only reach `/v1/me` and the 2FA enrolment endpoints (403 `2fa_required` elsewhere), on existing sessions too; they can't turn it off. Admin-token and proxy sign-ins are not asked for codes (the token is break-glass; the identity provider owns MFA for proxy users).
  - Trusted proxy sign-in (opt-in, `modules/auth/proxy-auth.ts`): `THEIRSIDE_AUTH_PROXY=header` takes the email from `THEIRSIDE_AUTH_PROXY_HEADER` (default `X-Forwarded-Email`; oauth2-proxy, Pomerium, Cloudflare Access…), `alb` verifies AWS ALB's `x-amzn-oidc-data` JWT: ES256 with the public key ALB publishes per key id (`https://public-keys.auth.elb.<region>.amazonaws.com/<kid>`, cached; region and partition from `THEIRSIDE_AUTH_PROXY_ALB_ARN`), `signer` must be that ARN, unexpired (60 s leeway), ALB's `=` padding tolerated, `email` and `name` claims. The header is believed only when the TCP peer (never `X-Forwarded-For`) is in `THEIRSIDE_AUTH_PROXY_TRUSTED_IPS` (required; addresses/CIDRs, IPv4-mapped IPv6 unwrapped); from anyone else it is ignored and the request is treated as if it weren't there. Each request is authenticated by the header (no session); writes need the CSRF token (HMAC of `proxy:<user id>`) because the proxy's own cookie is ambient. An unknown email signs in when it has a pending invite (accepted on the spot), or with `THEIRSIDE_AUTH_PROXY_AUTO_CREATE=true` (also creates the default org on an install without bootstrap); otherwise 403 `no_account`. Proxy users (`auth_source = 'proxy'`) have no password and aren't asked for 2FA. Order: Bearer admin token, proxy header, session cookie.
  - Break-glass: `THEIRSIDE_ADMIN_TOKEN` still signs in (`POST /v1/auth/login {token}`, or `Authorization: Bearer` for scripts) as a system user `usr_admin_token` (owner of the first org, never listed, no account settings). Unset it to disable.
  - Removing a user cascades to their sessions; nobody removes themselves or the last user who can sign in.
- Bootstrap (self-hosted, `THEIRSIDE_BOOTSTRAP_API_KEY` set, no org yet): org, project, the key (scopes `ingest` + `read`) and a status page with a random token, so SDKs can send before anyone signs in. No user: the setup page creates the first. Idempotent; on later starts it only ensures the key exists.
- API keys: per project, stored hashed (SHA-256) with a 13-character display prefix, prefixed (`tsd_live_` + 32 base62), scopes `ingest` and `read`. Lookups are cached 60 s, so revocation takes effect within a minute.
- Entitlements: `entitlements.for(orgId)` returns a typed object (`maxProjects`, `retentionDays`, `networkView`, `slaReports`, `sso`, `rbac`, `auditLog`, `maxOrgs`, `maxStatusPages`, `customStatusDomain`, `whiteLabelStatusPage`, `pagingIntegrations`, `monthlyCallLimit`); the editions table in §2 maps them to features.
  - Self-hosted: defaults to the OSS set (`maxProjects: null`, `retentionDays: null` = use `THEIRSIDE_ROLLUP_RETENTION_DAYS`, `maxOrgs: 1`, `maxStatusPages: 1`, all paid booleans false, `monthlyCallLimit: null`); a licence key (`THEIRSIDE_LICENSE_KEY`, Ed25519-signed JWT verified offline with an embedded public key, no phone-home) upgrades it. Expired licence degrades to OSS, never stops ingest or alerts.
  - Licence format: header `{"alg":"EdDSA","typ":"JWT"}`, payload `{iss:"theirside", sub:<licensee>, plan, iat, exp, ent:{<entitlement fields>}}`. Only known entitlement fields with the right type are applied. One licence covers the whole install.
  - Keys: `PRODUCTION_LICENSE_PUBLIC_KEYS` (`apps/collector/src/modules/entitlements/keys.ts`) is empty until the production signing key exists. A clearly marked dev keypair (`dev-keys.ts`) signs test licences, accepted only with `THEIRSIDE_ALLOW_DEV_LICENSE=1`. Tooling: `pnpm --filter @theirside/collector licence keygen|sign|verify`.
  - Cloud: resolved from the org's plan by a resolver plugged in through `EntitlementsResolver`.
- Usage metering: `usage_daily(org_id, project_id, day, calls_ingested, events_dropped_reported)` updated on ingest. Feeds limits. `monthlyCallLimit` (UTC calendar month, whole org) is enforced only when set: the batch is rejected with 429 + `Retry-After`. Month-to-date usage is re-read at most once a minute per org.

## 5. Data model (Postgres)

### 5.1 Config tables
`orgs`, `users`, `memberships`, `projects`, `api_keys`, `providers` (project, name, host patterns, explicit routes, support email/URL/notes, public display name, `is_public`, `path_privacy` strict/balanced/NULL and `allowed_path_words`, migration 004), `alert_channels`, `alert_deliveries`, `status_pages` (project, public token, provider filter, theme), `settings` (per project overrides for incident thresholds), `sdk_instances` (service, environment, sdk version, last seen, dropped events), `usage_daily`, `sessions`, `auth_tokens`, `auth_throttle`, `user_recovery_codes` (§4), `install_meta` (per-install key/value: session secret, bootstrap admin id, last run of slotted jobs, future network `contributor_id`). Schema: `apps/collector/migrations/001_init.sql`. Provider rows are created automatically from names seen in traffic (with one seen host); users then fill in support contacts and public display names.

### 5.2 Event tables
- `events`: raw, declaratively partitioned by day of `received_at` (`events_YYYYMMDD`); columns per the shared schema plus `org_id`, `project_id`, `received_at`. Retention `THEIRSIDE_RAW_RETENTION_DAYS` (default 30); partitions for today and 3 days ahead created by the scheduler (and on demand if an insert finds none), whole days older than retention dropped.
- `rollups_1m`: (org, project, environment, provider, endpoint, method, minute) → total, ok, per-outcome counts (one column per outcome), `status_429`, latency histogram as columns `h0`…`h17` (buckets from `packages/shared/src/histogram.ts`), `latency_sum_ms`. Upserted in the ingest transaction from per-batch in-memory aggregates (one `INSERT … SELECT unnest(…) ON CONFLICT DO UPDATE`; keys sorted to avoid deadlocks). Retention default 90 days (entitlement-capped in cloud). All dashboards, scoring and the status page read rollups, never raw events; raw events are for samples (request IDs, error codes) and debugging.

### 5.3 Incident tables
`incidents` (environment, provider, scope: endpoint or provider, kind: errors or latency, status, opened/resolved, last alerted rate and p95, last evaluated minute, `alerts_muted`, peak error rate, peak p95, baseline snapshot, summary text, sample request IDs; columns added in `002_incident_alerting.sql`), `incident_endpoints` for grouped provider incidents (first seen, recovered, peak rate per endpoint), `baselines` (cached per endpoint: provider-error rate, 4xx rate, 429 rate, p50, p95, sample size, history minutes, `learning` flag, computed_at).

### 5.4 Network aggregate format (fixed now, used later)
A row = `rollups_1m` minus tenant identifiers: `host`, `method`, `endpoint`, `minute`, outcome counts, histogram, plus a random per-install `contributor_id`. Only providers matched to the catalog (`source = 'catalog'`, public known providers) may ever be converted; discovered-only domains and configured names never. Self-hosted uplink is opt-in, off by default.

### 5.5 Storage abstraction
Collector code depends on repository interfaces (`EventStore`, `RollupStore`, `IncidentStore`, `ConfigStore`, plus `UsageStore`), bundled as `Storage` with `transaction(fn)` (unit of work: ingest writes raw events, rollups, usage and the SDK heartbeat atomically) and `withLeaderLock(name, fn)` (advisory lock). Postgres implements all of them (`apps/collector/src/storage/`); only that directory contains SQL. Cloud can later move `EventStore`/`RollupStore` to ClickHouse without touching scoring or API code.

## 6. Ingest protocol

- `POST /v1/ingest`, `Authorization: Bearer <project api key>`, `Content-Encoding: gzip`, body `{ protocol: 1, sdk: {name, version}, service, environment, dropped, lastFlushError?, sampleRate?, events: [...] }`.
- Event: `{ ts (epoch ms, call start), provider (string, or null for a host found by auto-discovery: the collector assigns the provider), host, method, endpoint, status|null, durationMs, outcome, errorCode?, correlationId?, providerRequestId?, service?, environment?, sdkVersion? }`. The SDK sends `service`/`environment`/`sdkVersion` once in the header; the collector fills them into each event.
- `sampleRate` (0, 1], default 1: only `ok` events are sampled, so the collector weights `ok` events by `round(1 / sampleRate)`.
- Limits: 1 MB compressed, 16 MB decompressed (gzip-bomb guard), 5,000 events per batch. 413 above that, 429 when over plan limits (SDK backs off), 503 + `Retry-After: 30` when storage is down. Also 401 (missing/invalid/revoked key or no `ingest` scope; checked before the body is read), 400 (invalid JSON or schema), 415 (unknown `Content-Encoding`). Success: `202 {accepted: n}`.
- Unknown fields are ignored; protocol bumps only for breaking changes, and the collector accepts the previous version for at least 6 months. `provider: null` (auto-discovery) stayed protocol 1: collectors with discovery accept both forms; an older collector rejects such batches. The SDK detects it: a 404 on `GET /v1/sdk-config` turns auto-discovery off for that process with one always-on `console.warn`, drops discovered events already queued, and keeps recording listed providers. Upgrade the collector to get discovery.
- Provider assignment at ingest (`modules/discovery/directory.ts`): excluded hosts are dropped; a host already on a provider (exact or pattern) goes there; else the catalog (`packages/shared/catalog.json`, longest domain match) or the registrable domain (`tldts`, Public Suffix List incl. private suffixes). Hidden/internal providers drop their events (also for SDKs that send names). Caps: 300 providers per project (then the `Other` provider), 50 hosts per provider, 20 subdomains of the provider's domain fold into `*.domain`. `category = infrastructure` (AWS, Google Cloud, Azure, CDNs…) is created with alerts off: incidents are tracked and shown, muted.

## 7. Scoring and incidents

Full rules, formula and defaults: `docs/scoring.md`. Summary:

- Scheduler runs every minute, 5 s past the minute (and once on startup), and evaluates the last complete minute (scheduler jobs in order: partitions, incidents, alerts, discovery digest, template merge, rollup retention). The digest (hourly) and the template merge (03:00 UTC) record their last completed slot in `install_meta` (`job:<name>:last_slot`) and run whenever the current slot is newer, so a slot missed while the collector was down runs on the first tick after startup (several missed slots run once; a failed run is retried next tick; nothing recorded counts as due).
- Baseline per endpoint from the last 7 days of rollups, excluding the last 15 minutes and incident minutes. `learning` until ≥ 24 h and ≥ 500 calls; while learning the provider-error rate is max(observed, 1%). Cached in `baselines`, refreshed every 10 min.
- Provider errors: `http_5xx`, `timeout`, `conn_reset`, `conn_refused`, `dns`, `tls`. Weighted lightly: `http_4xx`, 429. Ignored: `aborted`.
- Score 0–100 over the last 5 min → green (≥ 90) / amber (≥ 60) / red. Provider score = volume-weighted, at least amber if any endpoint is red.
- Open incident: 3 consecutive minutes with ≥ 20 calls in the 5-min window and ≥ 3 provider errors and provider-error rate ≥ max(5× baseline, baseline + 5 pp) and one-sided binomial p < 0.001; or p95 ≥ 3× baseline and +1000 ms. Group endpoints of one provider (one open incident per provider). Resolve after 10 healthy minutes per endpoint; 30-min cooldown (incidents inside it are recorded but muted). Alerts on open, escalation (rate or p95 doubles for 3 windows, or another endpoint joins), resolve. Thresholds overridable per project (`settings.thresholds`).
- Every alert says whether the provider's other endpoints are healthy and carries a paste-ready summary for the provider's support.
- The incident job recomputes from rollups each tick and is idempotent per minute (`incidents.last_evaluated_minute`); the engine (`incidents/engine.ts`) is a pure function of the open incident and per-endpoint evaluations.

### 7.1 Alert delivery

- Channels (`alert_channels.kind`): `slack` (incoming webhook, Block Kit; config `{webhookUrl}`), `email` (SMTP via nodemailer; config `{to: []}`), `webhook` (config `{url, secret}`). Adapters implement `ChannelAdapter` (`alerts/channels.ts`); `ee/` paging integrations plug in the same way.
- Rendering (`alerts/render.ts`, snapshot-tested): Slack = header (event + provider), title, fields (duration, environment, provider support), one line per endpoint (error rate and p95 vs normal; 5 listed, then "…and N more"), the "other endpoints" line, the provider summary in a code block, an "Open in dashboard" button, plus a plain `text` fallback; every text is capped to Slack's limits (header 150, section 3000, field 2000, 10 fields, 50 blocks, fallback 4000). Email = multipart plain text + inline-styled HTML, subject `[Theirside] Acme Cards POST /v2/cards/:id/activate failing 38%` (non-open events prefixed with the event, e.g. `Incident resolved:`).
- SMTP: `THEIRSIDE_SMTP_URL` (`smtp://…:587` STARTTLS, `smtps://…:465` TLS) or `THEIRSIDE_SMTP_HOST` + `_PORT` (587, or 465 when `_SECURE`) + `_USER`/`_PASS`; TLS is required whenever credentials are set (`THEIRSIDE_SMTP_REQUIRE_TLS=false` to allow plain text). Examples for Gmail, SES and Postmark in `.env.example`.
- Links: alerts link to `THEIRSIDE_PUBLIC_URL/#/incidents/<id>`; without `THEIRSIDE_PUBLIC_URL` they carry no link (never a localhost one). Status page URLs, the embed snippet and `embed.js` fall back to the request's origin.
- Failed sends are stored and shown as an actionable message: `HTTP 404 from hooks.slack.com: no_service` (Slack's reason body), `connection failed (ECONNREFUSED): …`, `timed out after 10 s`, `SMTP authentication failed: 535 …`, `SMTP server rejected the sender or recipients: …`.
- Webhook signing: header `x-theirside-signature: t=<unix s>,v1=<hex HMAC-SHA256(secret, "<t>.<body>")>`, plus `x-theirside-event` and `x-theirside-delivery`. Body = the `AlertPayload` JSON (event, title, provider, environment, `kind`, endpoints with current and normal error rate and p95, `otherEndpointsOk`, `otherEndpointsText`, `summary`, dashboard `url` (null without `THEIRSIDE_PUBLIC_URL`), timestamps, `durationMinutes`, provider `support` contact). Fields are only ever added.
- Alerts are queued as `alert_deliveries` in the same transaction as the incident change, sent by the `alerts` job; failed attempts retry after 30 s, 1, 2, 4, 8 min, then `failed`. Every attempt updates the row (`attempts`, `last_error`, `sent_at`).
- Admin API (session or `Bearer THEIRSIDE_ADMIN_TOKEN`; writes need owner/admin): `GET/POST /v1/admin/alert-channels`, `PATCH/DELETE /v1/admin/alert-channels/:id`, `POST /v1/admin/alert-channels/:id/test` (synchronous send, returns the result), `GET /v1/admin/deliveries`. Secrets are write-only (returned redacted).

## 8. Security and privacy

- Collected per call: time, provider, host, method, endpoint template, status, duration, outcome, error code, optional correlation ID from the host app, optional provider request ID (value of allowlisted response request-ID headers only; can be disabled). Never bodies, query strings, other headers or raw paths.
- API keys hashed; webhooks HMAC-signed; status page exposes only providers marked public, no paths or volumes.
- Self-hosted collector makes no outbound calls except configured alert channels and SMTP (alerts, invites, password resets), AWS's ALB public-key endpoint when `THEIRSIDE_AUTH_PROXY=alb`, and (opt-in, later) network uplink.
- `docs/privacy.md` is the customer-facing statement and must match the code.

- 2026-11-04: A 404 on `/v1/sdk-config` means a collector older than auto-discovery, which rejects whole batches containing `provider: null`; rather than lose listed providers' events with them, the SDK turns discovery off for the process. The warning is the SDK's only log line that ignores `debug: false`: without it, a team would see missing providers and nothing to explain why. Discovery stays off even if the collector is upgraded mid-process; a restart turns it back on.
- 2026-11-05: The route learner keys tenant-style subdomains by `*.domain` and evicts least-used, after the overnight soak misfiled ~7% of a vendor's calls: 5,000 tenant subdomains filled the 500 LRU slots and kept evicting busy vendor hosts, which then re-counted to 5 and sent provisional `:id` templates meanwhile. Folding follows the collector's rule (20 subdomains) so both sides group the same hosts; the SDK approximates the registrable domain as the host minus its first label to avoid shipping the Public Suffix List, and takes the collector's folded patterns from the remote config (`tenants`, additive) when it has them. Only folded `*.<provider domain>` patterns are sent, not catalog or hand-made wildcards: sharing a key across e.g. all `*.googleapis.com` APIs would collapse their resource names into `:id`. Privacy trade-off: sightings across tenants pool, so a value seen 5 times across tenants of one domain counts like 5 times on one host.
- 2026-11-05: The SDK's path-word vocabulary is mined from the APIs.guru OpenAPI directory (CC0 1.0; ~2,500 APIs across domains): words used in path segments, or parts of them, by at least 5 APIs, plus a hand-written seed list, minus personal names from popular-names-by-country-dataset (CC0 1.0) unless at least 5 providers use the word (`mark`, `max`, `min`…: the documented residual risk). Only single words are taken from the specs; nothing else is stored. The mining script is in `tools/vocabulary/` so the list can be rebuilt; the committed output is a ~15 KB word string bundled into the SDK.
- 2026-11-05: Path privacy is decided by the kind of word, not only by frequency. The 2026-11-05 soak sent ~1,400 synthetic names: an API with a small set of customers called often makes their names as "frequent" as resource words, which no count can tell apart. `strict` (default) sends a plain path word only when every part of it is a vocabulary word mined from real APIs (or a provider's allowed word), on top of the 5 sightings; the distinct-value cap drops from 32 to 16 so word-made slugs collapse sooner. Cost: domain words outside the vocabulary show as `:id` until allowed or routed; `balanced` (per provider, or init()) restores frequency-only for teams whose paths carry no personal data. Strict wins a disagreement between init() and the dashboard unless the dashboard explicitly sets balanced for that provider, because the dashboard setting is the per-provider, considered choice. Dates (`2024-06-01`) stay collapsed by the static ID rules: a date in a path can be a birth date.
- 2026-11-05: In strict path privacy a word that passes the vocabulary (or allowed-words) check is sent from its first sighting; the 5-sightings rule now applies only in balanced. The vocabulary already answers "is this safe to send", so waiting added nothing for privacy and cost accuracy: a soak with realistic mixed-domain traffic kept misfiling calls as provisional `:id` templates because ~60 busy hosts × ~20 slots overflowed the 500 slots and evicted counts. The 16-distinct cap stays in both modes; under eviction it can only let through a few more vocabulary-word slug values, never a name. Slots are also keyed per provider (init() providers, and the collector's multi-host providers sent in the remote config within a byte budget) instead of per host, so a provider's api/files/sandbox hosts share one set of slots. Trade-off: hosts of one provider with different APIs share the 16-value cap, so a big multi-API provider collapses a position sooner.
- 2026-11-05: `@theirside/shared` is private (never published): the SDK bundles its code (tsup `noExternal`) and now also inlines its types (`dts.resolve` with a `paths` mapping to the source), because the published `.d.ts` imported `@theirside/shared/core` and would have broken every TypeScript consumer. The compat smoke fails if `dist/` mentions `@theirside/shared`. The SDK is published with `pnpm publish` (applies `publishConfig.exports`); `repository`/`homepage` are left out until the repo is public (TODO in the SDK README).
- 2026-11-05: The collector image is published to ghcr.io (`ghcr.io/theirside/collector`) by a tag-triggered workflow using only `GITHUB_TOKEN`: no registry secrets to manage, and the image links to the repo through its `org.opencontainers.image.source` label. Docs pin an exact version; teams that need their own registry mirror it (ECR example in `docs/nestjs-integration.md`). The compose file keeps its `build:` section and defaults to the never-published tag `:local`, so `--build` (demo, CI smoke, e2e) can never shadow a released tag. A release version must pull or fail: compose has no conditionals and falls back to a build when a pull fails, so compose passes `THEIRSIDE_VERSION` as a build arg and the Dockerfile's first step exits with an explanation unless it is `local` (plain `docker build` and the release workflow use that default). A silent source build under a release tag would run unreleased code while reporting a release version.
- 2026-11-05: The shared admin token is replaced by built-in user accounts in the free edition, because a team sharing one secret can't tell who did what, revoke one person or survive the token leaking; the token stays as break-glass. All users are equal (no roles) so nothing that a single team needs is gated. Sessions are server-side rows (cookie token hashed) instead of the stateless HMAC cookies, because sign-out, "sign out everywhere" and revocation on a password change need state. CSRF uses an HMAC of the session plus an Origin check rather than a stored token, so nothing extra is stored and proxy identities can use the same scheme. Throttling lives in Postgres (an atomic upsert) so replicas share the counts, and an account lock applies to unknown emails too, accepting that anyone can lock an account for 15 minutes in exchange for not revealing which emails exist. argon2id comes from `@node-rs/argon2` (prebuilt binaries for every image architecture, no install scripts); Node's own `crypto.argon2` needs 24.7+, and the collector supports older Node. Bootstrap no longer creates a credential-less admin: the first user comes from the setup page, protected by the admin token or a per-instance setup code from the log.
- 2026-11-05: Two-factor sign-in is TOTP with recovery codes, written against `node:crypto` (RFC 6238 is ~40 lines) rather than a dependency. TOTP secrets must be readable to check codes, so they are encrypted with a key from `THEIRSIDE_SECRET_KEY` rather than hashed; the key is an environment variable, not stored in the database, so a database dump alone yields no secrets. Losing the key costs only 2FA (recovery codes and other users still get people in), which is why it is not derived from anything in the database. Replay protection stores the last accepted step per user instead of a used-codes table. When the org requires 2FA, the restriction is checked per request, so it applies to sessions that already exist.
- 2026-11-05: Trusted proxy sign-in decides trust by the TCP peer address, not by a shared secret header or `X-Forwarded-For`: the proxy is what a self-hosted team already runs in front of internal tools, and a peer address can't be forged over TCP while forwarded headers can. The ALB mode verifies the JWT itself instead of trusting the IP check alone, because an ALB in the same subnet could belong to another app; the `signer` must be this ALB. No JWT library: ES256 with `node:crypto` covers ALB's single format, including the `=` padding that strict JWT libraries reject. Proxy users have no session (every request carries the identity), so sign-out is the proxy's job; unknown people need an invite unless auto-create is on, so an IdP that lets in the whole company doesn't make everyone a Theirside user by default.
